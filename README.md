# Telegram Bot Authentication (`tg-bot-auth`)

این ریپازیتوری شامل یک **کد تمرینی و پرامپتی (Prototype / PoC)** برای پیاده‌سازی سیستم «ورود به سایت با تلگرام» (Telegram Login) از طریق مکانیزم **Deep Linking** است. هدف از این نمونه‌کد، نمایش منطقِ پشت صحنه و ایده اصلی این نوع احراز هویت است و می‌توانید از ساختار آن به عنوان یک **پرامپت (Prompt) و الگو برای ابزارهای هوش مصنوعی** استفاده کنید تا کد نهایی را برای سیستم شما تولید کنند.

## 💡 جریان کار پروژه (Workflow)

1. **تولید توکن موقت:** کاربر در مرورگر وارد صفحه لاگین می‌شود؛ فرانت‌اند یک درخواست ارسال کرده و سرور یک توکن یکتا تولید و با وضعیت `pending` ذخیره می‌کند.

2. **هدایت به ربات تلگرام:** فرانت‌اند یک لینک اختصاصی با فرمت `tg://resolve?domain=YOUR_BOT&start=TOKEN` می‌سازد.

3. **پردازش Webhook:** با کلیک کاربر روی لینک و استارت کردن ربات، تلگرام دستور `/start TOKEN` را به وب‌هوق سرور ارسال می‌کند. سرور توکن را اعتبارسنجی کرده و وضعیت آن را به `loggedIn` تغییر داده و مشخصات کاربر را ثبت می‌کند.

4. **بررسی لحظه‌ای (Polling):** بخش فرانت‌اند هر چند ثانیه وضعیت توکن را بررسی می‌کند. به محض تایید، توکن را ذخیره کرده و کاربر را به داشبورد هدایت می‌کند.

## 📝 ساختار فایل‌های پروژه

* `getToken.php`: ساخت توکن یکتای موقت و افزودن آن به لیست.

* `webhook.php`: دریافت درخواست استارت از تلگرام و تغییر وضعیت توکن به لاگین‌شده.

* `check_status.php`: بررسی وضعیت توکن توسط فرانت‌اند.

* `login.php`: صفحه ورود کاربر و هدایت به تلگرام.

* `dashboard.php` & `user.php`: صفحه داشبورد و دریافت مشخصات کاربر لاگین‌شده.

* `.tokens.json`: فایل ذخیره‌سازی موقت توکن‌ها (صرفاً برای حالت تمرینی).

## 🚀 پیاده‌سازی در دنیای واقعی (بر روی هر فریم‌ورک و زبان برنامه‌نویسی)

این منطق کاملاً عمومی است و منحصر به زبان یا فریم‌ورک خاصی نیست. شما می‌توانید همین فرآیند ذهنی را روی **هر زبان یا فریم‌ورکی** (مانند Node.js, Python/Django, PHP, ASP.NET, Go و ...) پیاده‌سازی کنید.

برای پیاده‌سازی در محیط واقعی، تنها کافیست نکات زیر را رعایت کنید:

1. **دیتابیس / Redis:** جایگزینی فایل متنی ساده با **Redis** یا دیتابیس (برای سرعت بالا، امنیت و تعیین زمان انقضا/Expiration برای توکن‌ها).

2. **مدیریت نشست‌ها:** صدور توکن‌های استاندارد مانند **JWT** یا **Session**های امنیتی فریم‌ورک شما پس از لاگین موفق کاربر.

3. **ارتباطات زنده (اختیاری):** استفاده از **WebSockets** به جای Polling مداوم HTTP برای بررسی لحظه‌ای وضعیت لاگین.

## 🤖 استفاده به عنوان پرامپت هوش مصنوعی

شما می‌توانید کل این منطق و فایل‌های نمونه را به هوش مصنوعی (مثل ChatGPT, Claude یا Cursor) بدهید و از آن بخواهید:
> *"بر اساس این منطق و جریان کاری (Workflow)، کد ورود با تلگرام را برای فریم‌ورک [نام فریم‌ورک شما] با دیتابیس [نام دیتابیس شما] پیاده‌سازی کن."*
